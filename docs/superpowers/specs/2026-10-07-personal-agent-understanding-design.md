# 个人 Agent：了解用户与多事项持续协作

状态：早期设计草案，已被 [结构化人物描述与选择性上下文](2026-10-07-personal-profile-design.md) 取代。本文保留多事项协作的探索背景，不作为当前实施依据；没有实施对应功能。

## 1. 设计目标

个人 Agent 应能了解用户同时关心的多件事，在每件事上保留上下文、决定与真实进展，并结合整体处境帮助用户协调。用户无需先选出唯一目标，也无需反复向每个会话介绍自己。

了解用户在交流和共同做事中逐步形成。用户背景、事项及安排均可修正；缺少信息不能被填成确定事实。项目 `agent.md` 所描述的研究、毕业与就业是起始场景，不限定可记录事项的范围。

## 2. 方案取舍

| 方案 | 优点 | 代价 |
|---|---|---|
| 先建立完整用户档案 | 初始背景较齐全 | 初次负担大，尚未发生的偏好容易被固定 |
| 从多任务清单出发 | 容易开始行动和展示进度 | 用户动机、现实限制及事项关系容易丢失 |
| 持续用户背景、事项记录与整体协调 | 支持同时推进、自然积累和随时纠正 | 需要管理信息来源、事项归属与更新冲突 |

推荐第三种。第一版使用一个主 Agent 与可检查的记录，不增加固定角色团队或额外工作流引擎。

## 3. 建议采用的概念

- **用户背景**：影响协作的目标、处境、资源限制和偏好；每条认识独立保存来源、时间、适用范围及确认情况。
- **事项**：用户希望持续关注、探索或推进的一件事，可以是研究方向、求职准备或尚无明确结果的困惑。事项允许长期存在、暂缓、改变方向或结束。
- **进展**：已经发生并有来源的变化，例如新增材料、实验结果、用户反馈和完成的行动。
- **决定**：用户已作出的选择，记录适用事项和有效范围，可被后续决定替代。
- **下一步**：当前值得采取的一项行动或需要回答的问题，可以是讨论、阅读、整理、执行或等待外部结果。
- **近期安排**：多个事项在一个有限时期内的推进建议，包括用户要做什么、Agent 能做什么，以及时间和资源约束；经用户选择后成为当前安排。
- **执行任务**：一次有执行边界的 Agent 操作，产生可检查的成果；一个事项可以对应多次执行任务，一次任务也可以帮助多个事项。

事项不要求都有截止时间或固定任务分解。“想了解就业方向”可以先保留为探索；“等导师反馈”可以保持等待。会话是交流载体，事项可以跨会话继续。

## 4. 初次交流

### 开场

> 最近你有哪些事情希望一起推进？可以一次说几件，也可以先把零散想法告诉我。哪些有时间要求、哪些已经开始，知道多少就说多少。

用户自由表达后，Agent 整理目前理解的事项，展示来源于用户的事实、尚不确定的理解，以及可能的关联。每轮只追问最影响下一步安排的问题，不一次要求用户填写完整背景。

### 具体例子

用户说：

> 最近要做论文实验，下周准备组会，同时还想开始找实习。

Agent 可以整理为：

| 事项 | 当前已知 | 需要进一步了解 | 可能的关联 |
|---|---|---|---|
| 论文实验 | 正在推进 | 研究问题、已有结果、当前卡点 | 实验结果可能支持组会材料 |
| 组会准备 | 下周需要 | 具体日期、汇报内容、已有材料 | 可能复用实验记录 |
| 实习准备 | 希望开始 | 目标方向、进度、有无申请期限 | 与实验竞争可用时间，技术成果可能支持简历 |

“实验结果支持组会”及“研究成果可用于简历”只是待核对的建议，不能自动认定为已确认关系。相对日期按消息时间与用户时区解释；需要实际排程时确认具体时间。

接着提出一个有用的问题，例如：

> 这些事情近期有什么必须满足的时间要求？没有固定期限的也可以继续保留。

再结合回答提出近期安排，不要求放弃其他事项或选出永久唯一主线。

## 5. 对用户的认识如何形成

用户背景按条管理，主要覆盖：

1. 长期方向与重要诉求。
2. 近期处境、硬期限、可用时间与资源。
3. 能力和已有材料，仅保留与实际协作有关的部分。
4. 协作偏好，例如回复方式、主动程度、允许读取的材料范围。

每条记录至少包含内容、来源消息或材料、记录时间、适用范围，以及“用户明确表达 / Agent 推测 / 用户确认”的依据类别。依据类别与是否已生效分开；用户明确表达不代表它在所有未来场景永久适用。

对话中可以使用用户当前明确提供的信息。跨会话背景沿用候选、确认生效、失效的机制；Agent 提炼的候选不能自动激活。可以让用户一次核对一组事项与背景，避免逐句弹出确认。

用户说“先暂停求职，专注这一轮实验”时，更新的是相关事项状态与近期安排。不能据此推断用户永久不想找工作。确认后的纠正替代旧的有效认识，旧记录保留为历史并不再直接注入当前背景。

“暂停”“删除记录”“不再主动提醒”是不同操作，需要分别表达和执行。记住偏好不意味着获得读取文件、对外发送或定时执行的授权。

## 6. 每件事保留什么

每条事项记录最少保存：

- 稳定 ID、标题，以及用户希望关注或推进的原因。
- 用户所表达的期待；探索阶段允许为空或暂不确定。
- 当前处境、最新进展、已作决定、未解决的问题和来源。
- 材料、工作空间、相关会话与执行成果的引用。
- 期限、可用资源、等待对象；未知就明确记录未知。
- 当前状态：探索中、推进中、等待中、暂缓或结束。
- 建议下一步、是否获准执行、与其他事项的已确认关系。

下一步建议与已授权行动分开。提出“阅读三篇论文”不表示已经执行，工具执行成功也不自动表示该事项达成。

用户一次提到多个事项时，先识别分别属于哪件事；一个材料可关联多个事项。修改某个事项的进度或决定，只影响该事项和确实有关的安排。

## 7. 多件事如何协调

主 Agent 每次回应时先识别当前涉及的事项，再结合必要的整体背景。只有发现会影响其他事项的期限、依赖、材料复用或资源冲突时，才提出跨事项协调。

协调过程：

1. 区分明确期限、用户选择的优先事项、以及 Agent 的建议。
2. 找出等待关系和可复用成果。
3. 核对现实容量，例如本周可用时间、设备、模型预算与必须由用户完成的工作。
4. 给出可执行的近期安排，说明每件事为什么这样推进。
5. 用户调整后保留当前选择；出现新信息时提出修订，不默默重排。

第一版不使用隐藏的总优先级分数，不自动把所有事项排成严格顺序，也不要求所有事项同时发起后台执行。独立且获授权的资料整理可以委派现有子 Agent；主 Agent 仍负责结果整合与事项更新。

例如，在确认组会截止时间后，可以建议先整理现有实验结果用于汇报，同时准备实习资料清单；实验任务依设备和时间继续推进。具体安排需结合真实进度和可用时间，不能在信息不足时编造工期。

## 8. 日常交互与界面

首页以对话为主，增加“当前事项”入口，展示各事项的最新进展、近期时间要求、等待原因与下一步。用户可以展开查看详情、切换当前交流事项、纠正记录、暂停或结束事项。

用户可以自然地说：

- “实验跑完了，结果在这个目录里。”
- “实习先放一放。”
- “组会提前了，帮我调整一下。”
- “这几件事目前各到哪一步了？”
- “我本周只有两天空闲，有哪些值得先做？”

每次打开不强制播报所有事项。用户询问整体进展时展示总览；当前消息涉及某件事时进入对应背景；事项归属会影响执行而无法判断时再询问。

第一版的主动性是在交流中指出重要期限、冲突和可复用成果。关闭页面后的定时跟进、通知与自动执行，需要单独设计并获得用户授权，不作为本次默认能力。

## 9. 与现有项目衔接

现有会话日志和长期记忆可保存带来源的用户背景候选；现有激活、失效和版本校验机制继续使用。当前基于词项匹配的记忆召回不保证获得完整事项状态，因此需要显式的事项记录及关联，不能只依赖相似度搜索。

事项与进展通过 SQL 持久化，和执行任务保留关联；工作空间用于材料定位，不直接等同于事项。研究证据仍来自研究流程的实际材料，不从用户背景里推导。

执行前组装“相关用户背景 + 当前事项 + 必要的跨事项约束 + 近期交流”；执行后保存真实成果，生成事项更新建议。只有有明确依据的更新才能进入当前状态；Agent 的推断保留为候选。

此次设计草案不规定最终 SQL 字段、迁移方式和工具参数。用户确认交互及记录边界后，再制定实现计划。

## 10. 第一版范围与验收情境

第一版覆盖自然交流建立多事项记录、用户背景确认与纠正、跨会话续接、事项进展和材料关联，以及按期限和资源提出近期安排。

以下情境应可检查：

1. 同时提出三件事，均被保留，不强制只选一件。
2. 实验产物可关联组会，相关关系经核对后可复用。
3. 结束会话后继续某件事，能说明此前的进展、决定与未解决问题。
4. 暂缓求职不影响实验推进，也不被解释为永久偏好。
5. 不知道可用时间时先核对，不生成虚构的排程。
6. 无法访问本地材料时说明缺少依据，不声称已有新进展。
7. 用户纠正期限或偏好后，下一次上下文采用新版本。
8. 接近期限时能在相关交流中指出，但未经授权不创建定时提醒或发起对外行动。

## 11. 下一步需确认的交互选择

建议默认采用自然对话建立与更新事项，同时提供可编辑的“当前事项”列表供核对。用户不必每次填写表单，也能直接查看 Agent 当前理解。

请用户先审阅这一交互方向和信息边界。实现计划在设计确认后展开。
