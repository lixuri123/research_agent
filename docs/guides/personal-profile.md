# 结构化人物描述

工作台左下角头像设置中的“关于我”提供人物属性管理。属性名称开放，可以逐步添加，例如 `学习经历 / 研究方向`、`协作方式 / 解释偏好`，也可以使用完全不同的名称。

## 操作

1. 运行根目录 `start.bat`，打开工作台，点击左下角头像，再选择“关于我”。
2. 点击“添加属性”，填写属性名称和内容。点击“添加分类”增加上级层次，每一层单独填写；名称本身可以包含 `/`。
3. 内容可选文本、数字、是/否、列表或对象，以及暂未确定。列表或对象填写 JSON，例如 `["论文实验", "组会"]` 或 `{"每周时间": 8}`。
4. 保存后进入“待确认”。核对后点击“确认”，成为“已确认”。
5. “修改”保存新版本并重新进入待确认；“标记失效”保留历史但标记该认识已不适用。
6. “历史”显示各版本的内容、状态、来源与更新时间。删除同时移除当前属性及其人物属性历史；数据库备份不由此自动清除。

个人属性默认适用于个人，也可以记录特定项目或会话范围。手工填写的来源记录为“关于我面板”；接口调用还可以提供对话或材料引用。引用目前由调用者提供，系统不自动核验其对应来源的实际存在。

## 本次范围

人物属性支持手工管理、持久化、确认状态、版本历史和并发修改保护，尚未自动从对话提炼。普通 Agent 已支持选择性加入已确认且相关的属性；不会把整个人物描述默认加入所有问题，详见 [上下文组装](context-assembly.md)。人物属性仍单独保存，不会自动成为长期记忆。

更新代码后重启 API，刷新网页。新增表通过 API 启动时初始化，不需要重建已有数据库。API 和工作台使用当前 `DATABASE_URL`；默认本地单用户 `person_id=local`，API 仍沿用现有本地单用户权限边界。

## API

| 操作 | 接口 |
|---|---|
| 读取当前人物属性 | `GET /profile` |
| 新增属性 | `POST /profile/attributes` |
| 修改属性 | `PUT /profile/attributes/{id}` |
| 确认属性 | `POST /profile/attributes/{id}/confirm` |
| 标记失效 | `POST /profile/attributes/{id}/invalidate` |
| 读取历史 | `GET /profile/attributes/{id}/history` |
| 删除属性与历史 | `DELETE /profile/attributes/{id}?expected_version=N` |

新增请求示例：

```json
{
  "path": ["学习经历", "研究方向"],
  "value": ["个人 Agent", "持续协作"],
  "basis": "user_stated",
  "source_refs": [{"type": "user_edit", "id": "profile-ui"}],
  "scope": "person",
  "scope_id": null
}
```

更新请求除上述内容外需增加 `expected_version`；确认与失效请求为 `{"expected_version": N}`。旧版本修改返回 409，未知属性返回 404，字段不符合要求返回 422。每次保存、确认和失效都会产生新版本；若另一页面已更新，请重新读取后操作。

属性路径最多 12 层，每层 1–120 字符；单个 JSON 值最多 32 KiB 和 12 层，数值必须有限。值可以为空值。来源类型开放，确认依据限于 `user_stated`、`user_confirmed`、`inferred`；由用户明确确认后依据更新为 `user_confirmed`，此前推测保留于历史。

SQL 新增表为 `person_attributes` 与 `person_attribute_versions`。当前版本及历史同事务提交，按 owner 隔离；删除同事务移除两者。
