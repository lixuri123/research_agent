# 普通问候与模型输出协议修复

状态：用户根据逐项定位与改法批准实施。

证据：用户提供的追踪中，一次“你好啊”有五次模型调用。规划返回 DSML 文本，首次决策两次格式失败后原样重试，最终查找无关记忆并生成冗长回复。

选择明确协议与有反馈修正，保留严格 JSON/schema 校验；不截取混合协议中的 JSON 后直接执行。默认 prompt 模式保持 OpenAI 兼容服务可用，提供显式 json_object 配置，不根据模型别名猜测能力。格式修正最多一次，与网络重试分别限制和统计；反馈不包含原始返回文本或凭证。模型调用前继续保留预算预留，修正消息改变后重新计算输入预算。

完整且仅为问候的消息走一次简短文本调用，不搜索记忆、不发现工具、不做规划；带任务的问候、明确选择 Skill 或工具授权的任务继续原流程。回复及检查点、报告、预算仍持久化。已启动旧任务保持原检查点恢复逻辑。

一般任务的规划使用独立提示词，无工具目录和执行协议；拒绝 DSML/空规划，最多修正一次，保存合法计划后再执行。执行提示词只在回答需要历史背景时使用 memory_search，不把记忆为空当作阻塞。

LangSmith 为输出校验创建独立 span；格式错误在该 span 可见，并为外层增加修正计数。测试离线模拟混合 JSON/DSML、无 JSON、网络错误、预算不足、纯问候及带任务的问候，同时验证复杂研究和委派回归。

不修改用户已有 .env 和 Provider 凭证，不调用真实模型收费接口。通过 README/.env.example 说明 JSON 模式和格式修正配置。
