# 手机控制与云端中继设计

日期：2026-10-07

状态：用户已确认书面方案并授权实施。

## 目标与范围

电脑继续运行现有 FastAPI、SQL 存储、Worker 和 Agent；手机通过网页发起任务、查看进度和结果、确认审批。公网使用 HTTPS 与 WSS，电脑主动连接中继，不开放本地业务 API 到公网。不引入邮箱、密码或账号注册体系，以显式设备配对建立控制权。

第一版支持一个本地服务实例连接一个中继、一台电脑绑定多台手机。中继可以服务多个独立电脑，但配对关系必须隔离；手机第一版仅操作其当前配对电脑。多个设备共享该电脑的本地单用户数据，不构成多用户隔离体系。

## 架构与数据权威

```text
手机网页 -- HTTPS/WSS --> 云端中继 <-- 主动 WSS -- 本地连接程序
                                                       |
                                                本地业务服务
                                                       |
                                             SQL 任务存储与 Worker
```

- 手机：连接状态、工作空间与会话选择、任务提交、事件显示、报告与文件提案审批。
- 中继：电脑登记、配对协调、设备凭证验证、连接路由、在线状态。独立部署，不运行 Agent。
- 本地连接程序：配对确认、持久化设备授权、方法分发、参数与资源检查、任务事件转发。
- 现有业务服务：任务提交、存储、执行、预算、工作空间权限、报告版本及文件提案复核。

任务与文件的权威存储在电脑。中继只保存设备、配对关系、撤销状态和必要审计元数据，不持久化任务正文、报告或文件内容。转发消息可短暂存在有界内存缓冲；不写入正文日志。模型凭证不进入远程协议。

本地 API 继续监听回环地址。远程方法调用显式业务适配器，不接收客户端指定的 HTTP URL，不提供通用代理或通用 Python/命令执行方法。若复用业务服务需要抽取现有路由逻辑，仅抽取本设计涉及的部分，不重构无关 API。

## 信任与加密

第一版把所配置中继及其提供的手机网页视为可信服务。HTTPS/WSS 加密传输，中继运行时可以读取消息；本设计不宣称端到端加密。用户选择远程访问时界面明确说明该边界。

自建或受信部署的中继、有效 TLS 证书及域名是上线前提。中继运维者控制网页代码及设备登记服务，因此其失陷不在本版本的保护范围内。对无权的普通客户端、中继误路由、跨电脑资源访问以及已撤销设备，仍须分别执行身份和资源校验。

不自行设计密码算法。凭证由密码学安全随机源生成；可校验凭证在服务端仅保存摘要，秘密不进入 URL 查询参数、访问日志、二维码长期凭证或前端 localStorage。

## 配对生命周期

1. 本地首次启用远程控制时生成稳定 host_id 和高熵电脑凭证；完成中继登记。电脑凭证写入工作空间外的受保护运行配置，Windows 优先使用系统凭证保护，不能保存在用户绑定的资料目录中。
2. 电脑点击添加手机，创建五分钟有效、一次性的配对邀请。邀请由电脑授权的连接创建，中继保存摘要、host_id、截止时间和状态。
3. 二维码携带手机页面地址与短期配对秘密。秘密放在 URL fragment，手机页面读取后立即清理地址并通过 HTTPS 请求提交，减少 URL 日志泄露。
4. 手机创建待配对设备；邀请原子占用，不允许被第二台设备重复兑换。扫码不能直接获得数据访问权限。
5. 电脑和手机显示同一核对码。用户在电脑确认设备名称和核对码；手机不能自行确认。拒绝、过期或电脑断线均不完成绑定。
6. 本地先持久化授权记录，再确认中继完成配对。手机只在本地与中继均确认后取得设备凭证；局部失败保持待完成状态，并允许同一事务幂等恢复，不提前显示成功。
7. 手机凭证通过 Secure、HttpOnly、SameSite Cookie 管理；前端没有读取长期凭证的需要。浏览器丢失该凭证后需在电脑重新配对。

配对状态：pending、awaiting_confirmation、authorized、rejected、expired、revoked。设备名仅作显示，不能作为身份。限速、失败次数限制、过期清理及一次性兑换均为第一版要求。

## 权限与撤销

电脑是最终授权权威。每条远程调用根据已验证的连接身份解析 host_id、device_id 和权限版本，不信任消息 payload 自报的 owner_id。手机数据操作仍映射到该电脑的本地单用户 owner；device_id 用于控制授权和审计，不替代数据 owner。

本地授权记录包括 device_id、名称、创建时间、最近连接时间、状态、权限版本及授予的能力。中继只能路由到凭证所属电脑；本地再次检查设备状态、方法白名单及工作空间范围。

第一版能力固定为查看已有工作空间/会话、提交任务、查看任务/结果，以及报告与文件提案审批。提交时使用已配置模型选项和已授予的能力，不接受额外扩大 MCP、Skill、目录读取或本地执行授权的参数。

新增目录、授予工具能力、Provider 配置、MCP 配置、记忆或人物属性管理、任意文件写入、通用终端不开放远程方法。授权工作空间范围在电脑管理，可选择个人对话和已存在工作空间；目录白名单及已有读取授权继续生效。

解绑先提交本地撤销与权限版本更新，再通知中继撤销 Cookie 凭证、删除活动会话并断开连接。中继不可达时保留同步记录，重连先同步撤销再接收业务消息。本地逐次检查确保残留凭证不能执行操作。关闭远程访问同样立即阻止新操作并断开电脑连接；不会取消已经进入 SQL 的任务。

撤销约束以操作授权检查为界：已经接受或正在提交的业务操作可能完成，不能承诺撤销会回滚已接受的任务或写入。

## 消息协议 v1

公网采用 WSS 双向连接；配对、静态页面和连接初始化采用 HTTPS。WebSocket 只负责传输，不自动提供身份、业务权限或任务持久化。

请求信封字段：version、type=request、request_id、host_id、method、payload；变更请求还必须提供 idempotency_key。响应含 request_id、成功结果或结构化错误。事件含订阅 ID、任务 ID、事件游标和 payload。设备身份来自服务端验证后的连接上下文，不来自请求字段。

第一版方法：

| 方法 | 行为 |
|---|---|
| host.status | 获取电脑与连接状态 |
| workspace.list | 返回授权范围内现有工作空间，不返回 allowed_roots |
| session.list / session.read | 返回授权范围内会话和消息 |
| model.list | 返回可选模型的最小展示信息，不返回密钥及连接配置 |
| task.create / research.create | 提交普通任务或研究任务 |
| task.list / task.read | 查询授权范围内任务及结果 |
| task.subscribe / task.unsubscribe | 按任务与游标订阅或结束事件流 |
| report.read / report.decide | 查看报告并决定具体不可变版本 |
| file_change.list / file_change.read / file_change.decide | 查看修改差异并决定具体提案 |

对每个对象 ID 解析真实任务与工作空间归属，不允许凭单独对象 ID 绕过范围检查。报告和文件审批沿用现有版本、review_hash、冲突及幂等语义。

手机连接通过 Cookie 认证，并验证 Origin；状态变更的 HTTPS 请求有 CSRF 防护，跨站 WebSocket 握手被拒绝。凭证不放到 WebSocket 查询字符串中。电脑连接使用独立电脑凭证验证。拒绝未知版本、未知方法、额外权限字段、无效参数以及超限消息。

应用消息最大 1 MiB；大文本响应分页或分块，单次审查内容超限时提示回电脑查看，不截断后允许审批。每连接缓冲最多 100 条消息且不超过 4 MiB，慢客户端溢出后断开并要求补读，不能阻塞 Worker 或无限积累内存。

统一错误至少包含 offline、unauthorized、forbidden、invalid_request、conflict、expired、rate_limited、internal_error。错误不能返回密钥、连接凭证或内部堆栈。

## 幂等、事件与断线

手机一次用户操作只生成一个幂等键，网络重试复用。现有 frontend/src/api.ts 中每次 createTask/createResearch 生成新 UUID 的逻辑需改成由调用方传入，避免远程重试产生新任务。

中继确认只表示收到消息；task.create/research.create 的成功响应必须在本地 SQL 接受任务后发送。响应丢失时使用原键重试，返回原任务。其他变更方法采用其业务版本校验与幂等处理，不依赖 WebSocket 发送次数保证执行一次。

本地事件保存有序游标。订阅时从 cursor 之后补读，再持续推送；手机按任务和事件 ID 去重。如果现有事件模型缺少可恢复游标，仅为已有事件补充这一能力。事件游标失效时明确发送 resync_required，由手机重新获取任务快照。

应用心跳每 20 秒发送一次，60 秒无有效响应视为断开。重连使用指数退避和随机抖动，等待上限 30 秒。重连必须重新认证、更新撤销状态并重新订阅，不沿用旧连接的授权缓存。

手机离线时已接受任务继续执行；恢复后获取快照和遗漏事件。电脑离线时显示离线，不接收新任务、不在中继持久化排队命令。刚断线时无法确定任务是否接受，手机显示“提交状态待确认”，在电脑恢复后以原幂等键确认，不能显示成功或自动创建新操作。

电脑恢复在线只恢复控制连接；业务任务恢复继续由已有 SQL 队列、Worker 续租和检查点负责。中继重启不改变业务任务状态。

## 手机与电脑界面

手机使用现有 React 技术栈，提供独立移动入口，复用类型、任务结果和审批组件。业务调用通过 transport 抽象：电脑 HTTP，手机 WebSocket。仅复用明确开放的业务方法，不把现有全部 api 对象暴露给手机。

手机界面包含电脑状态、空间/会话选择、任务输入、任务列表、任务详情、报告和文件差异审批。断线时保留输入草稿，禁用依赖在线状态的操作；草稿留在手机本地，不发送到中继持久化。

电脑设置新增“手机控制”：默认关闭、配置受信中继地址、开启连接、添加手机、设备列表、调整空间范围、解绑及关闭。首次开启说明中继可见消息内容、手机权限和电脑在线要求。

暂不开发原生手机 App，不提供浏览器后台持续在线承诺；页面打开时实时显示，重新打开时补读。后台推送、远程唤醒、离线任务队列、大文件传输、多实例中继和多用户云端工作台均不在第一版范围。

## 部署与接入

云端使用独立 FastAPI 服务、单实例运行、有 TLS 的反向代理及持久化数据库。第一版不使用 Redis；连接路由驻留内存，配对与凭证摘要保存数据库，部署重启后双方重连即可恢复。数据库备份只包含上述设备元数据。

本地新增 research_agent/remote 模块，负责协议、持久化授权、业务适配、配对和连接。作为独立连接进程运行，显式启用后由现有启动器管理，凭证不能出现在命令行参数中。API、Worker 与连接进程使用同一任务存储配置。连接进程退出或中继故障不能停止本地 API/Worker；状态显示故障并支持恢复连接进程。

第一版中继部署前必须具备域名、有效 TLS 证书与受信运行环境；具体服务商和域名由部署阶段确定，不影响协议与代码边界。首轮开发和测试使用本地测试中继及模拟设备，不接入真实模型、不对公网发布。

## 验收条件

1. 未配对、过期邀请、重复扫码兑换、未获电脑确认均不能访问业务数据。
2. 多电脑与多手机测试中不能跨电脑路由或绕过空间范围；伪造 host_id、device_id、owner_id 无效。
3. 解绑及关闭远程访问后，旧连接、旧凭证和断线重连均不能执行新操作。
4. 创建任务已提交但响应丢失时，原键重试只返回一个任务；断线状态不能误报成功。
5. 手机或中继断线不停止已接受任务；重连恢复事件且不重复显示，缓冲有界。
6. 报告版本变化、文件外部修改、重复或冲突审批仍沿用现有拒绝及幂等规则。
7. 未授权接口、跨站握手、CSRF 请求、超限消息与扩大工具授权参数被拒绝。
8. 中继持久化与日志没有任务/文件正文、Provider 密钥、长期凭证或配对秘密。
9. 手机窄屏可完成配对、任务提交、查看结果和审批；超限审查内容不能被截断后批准。
10. 中继不可用、连接程序退出或远程功能关闭时，本地 API/Worker 可正常使用。
