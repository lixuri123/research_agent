# 本地工作空间

工作空间绑定 API 所在电脑上的真实目录。一个空间可以容纳多个会话；切换会话不改变目录。任务携带 `workspace_id`，空间内的对话由服务端筛选，绑定及会话归属保存在已有 SQL 数据库中。旧会话保留在「个人对话」。目前列表显示当前空间最近 100 条任务。

## 使用

前端静态资源已构建。重启 API 和 Worker，刷新浏览器；左侧「工作空间」旁点击加号，输入名称及本地绝对路径，绑定后打开右侧文件区。

```powershell
# 在项目根目录，两个终端分别执行
$env:UV_CACHE_DIR = "$PWD\.uv-cache"
uv run python -m uvicorn research_agent.api:app --host 127.0.0.1 --port 8000
# 另一个终端
uv run python -m research_agent.worker
```

默认仅允许绑定服务启动目录及其子目录。需要使用其他项目时，在已有 `.env` 中添加目录白名单，API 与 Worker 使用相同配置并重启：

```dotenv
WORKSPACE_ALLOWED_ROOTS=["D:/agent/research_agent", "D:/projects/my-reproduction"]
```

请使用确实存在的目录，不把整个磁盘或用户主目录加入白名单。浏览器不能直接选择本机目录，这里的路径属于 API 主机；远程部署时不是浏览器所在电脑的路径。

## 读取与编辑

绑定时默认不授权模型读取。显式勾选「允许 Agent 按任务需要读取文本文件」后，普通 Agent 任务获得 `workspace_list`、`workspace_read` 只读工具，以及 `workspace_propose_write` 修改提案工具，只能访问其绑定空间。文件内容按需进入已配置模型调用，并留在任务工具记录中。提案不直接写文件；任务不会自动读取整个目录；同目录重复绑定不能改变授权。

右侧提供目录导航、UTF-8 文本/代码编辑与 Markdown 预览。保存直接更新原文件，保留 UTF-8 BOM；内容哈希不匹配时返回 409，保留编辑区内容，不覆盖磁盘。此时复制未保存内容，重新读取文件，人工合并再保存。离开文件或空间时提示未保存修改。

PDF、二进制、非 UTF-8、超过 128 KiB 的文件暂不预览。隐藏目录、环境文件、已知密钥/认证文件、依赖目录、符号链接、Windows 目录联接和硬链接受保护。白名单和文件名规则不是完整的数据防泄漏系统：普通代码或笔记也可能含有敏感信息，应在授权前检查目录。

## 当前边界

- Agent **不能直接写文件、创建/删除文件或执行终端命令**。它只能提交已有文本文件的修改提案，在消息下查看差异并「确认写入原文件」后，由服务端写入。拒绝提案不修改文件。
- 提案保存在 SQL 数据库中，与任务绑定，刷新页面后仍可审查。确认绑定不可变提案版本并复核原文件内容哈希；外部编辑导致冲突时不会覆盖，需重新读取并生成新提案。已应用提案重复确认不会再次覆盖。写入中断可使用「核对并完成写入」恢复。
- 提案包含原文与修改后全文，应与任务数据库一样保护。任务完成仅表示 Agent 完成本轮交付，不意味着提案已获批准或写入；文件区有未保存修改时界面会阻止确认。
- 原有「深度研究」图仍用于联网研究与证据审核；虽然任务归属工作空间，但不调用本地文件工具。处理本地材料请选择普通 Agent 模式。
- 普通 Agent 已接入范围匹配的长期记忆召回，见 [记忆说明](agent_memory.md)；这不代表跨会话研究状态已自动总结。
- 这是可信本机、单用户、loopback 服务；不支持多用户鉴权，也不是防恶意本机进程的沙箱。保存使用内容哈希及替换前复查，不能保证对恶意并发路径替换或所有外部写入的原子隔离。不要用 `0.0.0.0` 将文件接口暴露到公网。

接口：`GET/POST /workspaces`，`GET /workspaces/{id}/entries?path=`，`GET/PUT /workspaces/{id}/file`。`GET /tasks?workspace_id={id}` 筛选空间任务；空字符串筛选未绑定任务，省略参数保持原有全量列表行为。

提案接口：`GET /workspaces/{id}/changes?run_id=`，`GET /workspaces/{id}/changes/{change_id}`，`POST /workspaces/{id}/changes/{change_id}/decision`（`approved` 与 `review_hash`）。这是无鉴权的本地人工确认接口，不是能对抗恶意本机程序的授权隔离。
