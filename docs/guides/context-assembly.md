# 普通 Agent 上下文组装

普通 Agent 使用 `research_agent/context/` 统一选择背景。路由只决定带什么上下文，不改变工具权限或普通/研究执行模式。

## 自动路由

| 路由 | 触发依据 | 主要背景 |
|---|---|---|
| independent | 自包含问题或首次提出新目标 | 当前问题、真实补充要求；明确个人化请求可选择相关人物属性 |
| followup | “这个方案”“你刚才提到”“再详细一点”等明确前文依赖 | 最近有效对话中的锚点 |
| task | 明确任务 ID，或继续/推进/回顾/汇报 + 唯一完整标题 | 指定执行记录的目标、状态、结果与已保存进展 |
| multi_task | 多个明确目标，或明确要求枚举进行中任务 | 目标集合的摘要，最多 10 个 |

优先级为：显式 mode → 显式 task_ids → 正文任务引用 → 明确集合枚举 → 多目标比较 → 前文依赖 → independent。
同一会话和工作空间不是任务关联依据。“Redis 是什么”不会自动携带该会话里的论文任务。
无法唯一定位对象时返回澄清回复，不执行计划或工具。当前任务记录正常保存这条回复，不会自动恢复旧任务。

规则采用少量高精度模板和完整标题匹配，不使用模型路由、向量检索或模糊别名匹配。任务 ID 是最明确的引用方式。
“所有进行中的任务”按当前工作空间选择；超过 10 个时要求缩小范围。明确引用本人其他空间的任务只读取摘要，不继承其文件与工具权限。

## 请求参数

`POST /tasks` 可添加：

```json
{
  "task": "解释目前进展",
  "session_id": "my-session",
  "context": {
    "mode": "auto",
    "task_ids": ["已有任务的 task_id"],
    "profile_ids": [],
    "turn_ids": []
  }
}
```

缺省 context 等价于 auto。mode 可为 auto、independent、followup、task、multi_task。
independent 不允许同时提供 task_ids/turn_ids；task 最多一个 task_id；每类引用最多 10 个。
task_ids 可跨工作空间引用本人目标；turn_ids 必须属于当前会话与空间的有效历史。
profile_ids 必须符合人物属性的个人、项目或会话范围。
不存在或不可访问的引用返回 404；模式和参数冲突返回 422；相同幂等键但不同 context 返回 409。

## 人物与记忆

人物属性仍允许任意名称和嵌套值。自动选择仅在“结合我的背景/时间”等个人化请求中触发，根据属性路径和内容关键词匹配，最多 3 条；也可使用 profile_ids 明确选择。
只使用已确认且有效、范围匹配的属性。没有默认全局注入的“偏好”字段；同路径同范围的冲突属性自动选择时省略，明确引用时标记冲突。
人物 JSON 值保持完整结构，容量不足时省略整条，不产生破损 JSON。

独立问题不自动召回长期记忆；明确询问个人历史时例外。追问与任务关联可以召回相关有效记忆。
显式 independent 模式关闭自动记忆召回；执行过程中明确调用 memory_search 的工具结果仍按工具观察处理。
当前范围之外的属性、候选属性、失效记忆及提交之后更新的来源，不加入首次快照。

## 容量与恢复

`CONTEXT_INPUT_LIMIT` 默认 12000，使用 UTF-8 字节上界估算，不是准确 token 数，也不代表模型实际窗口。
输出空间单独记录为 `MAX_OUTPUT_TOKENS`；系统规则、当前问题、真实要求与输出契约不得静默截断。
历史、人物、记忆、旧任务的估算上限分别为 3000/1000/2000/3000，且必须满足全局输入上限。
多任务先公平分配最小目标/状态摘要，再加载额外内容；本次计划和最近工具结果优先于旧背景。
必需内容或任务最小摘要超限时明确返回容量错误，可以减少关联对象或增加配置限额。

首次选择保存固定路由与来源快照；恢复不会重新加入新对话或新人物版本。
每次调用前重新校验来源；撤销、删除或版本改变的人物/记忆被撤下，不自动切换到新版本。
必要任务或追问锚点无法读取时停止续接，而非无背景继续执行。

## 查看选择依据

任务详情接口的 `result.context` 包含 route、selected、omitted、warnings 和 estimated_input。
事件接口 `GET /tasks/{task_id}/events` 包含 `context_selected` 和来源撤下时的 `context_sources_removed`；事件记录来源 ID/版本和原因，不复制整个人物正文。
持久化阶段为 `agent_context_sources`、`agent_context_route`、`agent_context_manifest`，保存在现有 research_stages 表中。

## 更新与边界

更新后重启 API 和 Worker，并刷新工作台。前端静态资源已构建；数据库结构不需要迁移。
新 API 普通任务带 context_version=1；无此版本字段的旧任务沿用旧上下文路径，以免改变已经开始的执行。
深度研究尚未接入此模块，前端研究模式保留原来的最近会话拼接；研究节点和证据核验流程未改动。
子 Agent 沿用父 Agent 明确给出的目标、必要上下文及完成标准，不自动加载父会话或全局任务背景。
