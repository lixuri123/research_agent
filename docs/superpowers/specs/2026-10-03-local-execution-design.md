# 本地受限执行：第一版设计

状态：已确认总体路线；本文明确第一版边界，尚未实现系统级执行后端。

2026-10-03 补充：用户要求参照本机 dsh 重新设计，并确认实施 `2026-10-03-dsh-local-sandbox-design.md` 的首版可信固定只读操作路线。本文保留为历史严格隔离方案，不代表当前能力；dsh Windows 后端不提供系统级读取与网络隔离。当前首版如实报告 partial，后续任意代码或写操作仍未授权。

## 目标与范围

采用本地系统级权限限制、命令白名单与按风险审批。不建设云端执行平台，不要求 Docker，不提供通用编程终端。优先服务材料检索和整理，保持 uv 管理主应用环境。

第一版命令能力仅提供工作空间文本检索这一固定操作。列目录、读取文本、提交文件修改继续复用已有工作空间工具。暂不提供任意 Python 脚本、PowerShell、cmd、依赖安装、Git 写操作、文件删除或外部发布；未知操作默认拒绝，不因为点击批准就变为可执行。

## 权限边界

- 业务材料只来自当前任务绑定且已授权的工作空间。现有读取授权不自动变成命令执行授权，执行开关独立，默认关闭。
- 工作区外仅允许读取明确配置的程序、必要运行时、系统依赖。不得把整个用户目录或磁盘作为读取白名单。
- 执行目录和临时产物目录由服务端确定，不接受模型指定的绝对路径。
- 工作区内受保护文件仍禁止访问，包括环境变量、认证配置、密钥以及符号链接、目录联接和硬链接。按现有 WorkspaceService 规则校验。
- 第一版执行进程对业务工作空间只读；原文件写入仍由独立的修改提案确认接口执行。未来增加写命令需重新定义产物审查和写权限，不默认授予整个工作区写入权限。
- 命令子进程也必须受约束。设置 cwd、过滤路径、uv 虚拟环境均不等于系统权限限制。
- 第一版执行进程不联网。已有模型网关和联网检索工具是独立授权边界，不向执行进程传递它们的凭据。

## 命令白名单

模型提交结构化操作名和参数，不提交 shell 字符串。服务端将固定操作转换为固定可执行文件绝对路径和参数数组，不使用 shell=True。

文本检索只接受限定长度的普通文本查询、受校验的相对目录及受限制的结果数。服务端限定候选文件类型和大小，排除受保护路径。不开放任意程序路径、环境变量、额外 CLI 参数、管道、重定向或命令拼接。

程序必须来自服务端受信安装位置，不在工作空间中查找可执行文件，也不继承不受控的工具配置和凭据环境变量。程序缺失时报告不可用，不尝试由 Agent 安装。

## 系统级执行后端

Windows 后端需实际建立受限进程身份与文件访问权限边界，并对离线执行建立系统级网络限制；只修改代理环境变量不作为网络隔离验收依据。进程组统一管理，限制子进程、运行时间、内存和输出。

初始化不得默默更改用户项目 ACL、创建系统账户或安装防火墙规则。需要系统授权的安装步骤单独说明目标、影响和恢复方式，并由用户明确授权。管理员权限仅供受控初始化使用，不能给 Agent 或执行命令。

主应用启动和既有文件工具不依赖执行后端成功初始化。后端未配置、初始化失败或权限自检失败时，命令能力保持禁用，前端显示原因；绝不退回当前用户权限下的普通 subprocess。

不宣称能抵抗所有内核漏洞或恶意管理员；第一版提供经验证的文件、网络和进程权限约束，不是独立虚拟机。

## 风险与审批

- 当前任务已获执行授权，且固定操作通过参数与后端校验：工作区文本检索自动执行。
- 修改原文件：继续展示不可变提案与差异，用户确认后由服务端写入，并核对原文件版本。
- 超出文件范围、联网、任意脚本、安装程序、删除、外部发布：第一版拒绝。后续如增加能力，再为具体操作定义审批，不提供一键绕过系统边界。
- 判断是否允许由确定性代码完成，不为每条命令增加模型审核调用。

## 记录与模型上下文

记录任务、工作空间、操作、经校验参数、风险决定、开始结束时间、退出状态与截断信息。默认运行上限 15 秒、输出上限 16 KiB，超限停止并报告，不把完整日志无限追加给模型。

执行记录和文件提案分别保存。固定只读操作允许任务中断后重新执行；不将曾经的审批复用于另一条操作或另一工作空间。未来副作用操作不能照搬只读重试规则。

## 验证与实施顺序

1. 先验证 Windows 文件、网络及子进程约束确实可用，再接入 Agent 工具。
2. 增加独立执行授权、固定检索操作和有限执行记录；前端显示权限状态、实际操作及失败原因。
3. 保留既有提案确认机制，验证无执行授权时不能使用命令。

只进行少量边界验证：工作区内操作成功，区外读取及写入失败，受保护文件失败，网络失败，子进程不能脱离限制，超时清理有效，以及后端失败不降级。验收命令使用受控测试材料，不调用真实模型，不运行大量项目测试。

安全边界验证不能由命令白名单单元测试代替；未完成系统级验证前，不标记为可用沙盒。
