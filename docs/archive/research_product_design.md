# 面向科研的产品设计草案：研究问题、证据与验证

> 历史文档：保留设计与实施背景，当前结构请参阅 [目录说明](../architecture/directory-structure.md)。

状态：讨论稿，未开始实现。研究领域尚待确认；下面提供跨领域骨架，示例使用计算机/AI，不能直接套用为所有学科的方法标准。

## 1. 产品目标与切入点

帮助研究者回答三个问题：已有研究实际证明了什么？我的候选解释和已有证据是什么关系？下一项验证怎样区分竞争解释？

持续维护研究问题、证据与决策，综述是这些记录的一种导出。用户可以从一个具体问题开始，不必先建设完整实验平台。

备选方向：

| 方向 | 收益 | 代价 | 当前选择 |
|---|---|---|---|
| 文献证据与选题 | 从原文提取可比较证据、定位待验证问题 | 需要领域提取 schema 与人工校准 | 优先，现有检索及证据链可复用 |
| 实验复现与分析 | 管理代码、数据、运行与结果 | 强依赖学科、环境、资源和分析方法 | 第二步，先输出验证计划 |
| 贯穿研究生命周期的工作台 | 连通文献、实验与写作 | 范围过大，难以验证首批价值 | 长期方向，分开实现 |

初版聚焦：研究问题卡 + 文献证据矩阵 + 候选假设验证卡。

## 2. 一次完整使用过程

示例问题：“固定算力下，增加 RAG 检索数量是否仍改善回答质量？”

1. 用户填写问题与约束，系统协助明确目标、对象、比较条件和期望产物。
2. 系统提出检索策略与纳入规则，用户确认；保留查询、日期、来源、版本及每篇排除理由。
3. 逐篇提取方法、条件、指标、结果、局限，字段都有原文定位；缺失字段标 unknown，不补猜。
4. 系统生成证据矩阵。不同数据集、指标定义或预算的结果分组展示，不混为一个排行榜。
5. 对条件相近而结论不同的记录，提出待核验冲突，展示原文、差异和可能解释；研究者确认。
6. 用户提出假设，系统分别寻找支持证据、反证和替代解释，并形成验证卡。
7. 验证卡明确控制条件、基线、预期结果、失败判据及资源预算，供研究者决定是否执行。
8. 后续导入实验结果后，对假设状态作有依据的更新；保留原计划与所有修改记录。

初版交付到第 7 步；第 8 步的自动分析与实验执行单独设计。用户也可只使用文献矩阵，不被强制套入假设检验流程。

## 3. 核心功能

### 3.1 研究问题卡

字段：问题、学科、研究对象、研究目标、比较维度、约束、相关术语、检索范围、问题版本。

区分探索性提问、描述性整理与验证性假设。不要把宽泛主题直接当作可验证命题。

系统输出可编辑的问题定义、检索策略和完成标准；用户决定研究范围。规则修改产生新版本，旧版本及其筛选结果保留。

### 3.2 文献筛选与证据矩阵

每篇文献保留纳入/排除/待定状态、理由、原文范围及人工修改历史。重复发表或同一研究的多个报告建立关系，不能简单按 PDF 文件数统计独立证据。

跨领域基础字段：研究问题、方法、对象/样本、比较条件、指标定义、结果、局限、原文位置。学科扩展通过 schema 配置，不用统一的提示词猜全部字段。

AI 示例扩展字段：数据集及版本、数据划分、基线、模型与参数、随机种子、算力预算、评价程序、报告的不确定性、代码和数据可获得性。

每个提取值包含 value、unit、evidence_id、source_location、extraction_status；原文未报告、无法读取和不适用分别表示，不能都填空或零。

比较器给出 comparable / not_comparable / uncertain，并提供理由。相同指标名称也须核对定义；不同条件下仅可并列陈述，不能据此直接宣布方法优劣。初版不做自动合并效应或跨研究统计推断。

### 3.3 冲突与研究缺口记录

冲突候选必须指向至少两条证据，保留研究条件差异；解释由模型提出候选，用户确认，不自动认定两篇论文互相否定。

缺口记录采用限定范围的表达：“截至某日期，在当前检索范围内未找到满足这些条件的证据。”检索不到不能直接证明无人研究，覆盖范围不足则标为 uncertain。

每项缺口关联已检索范围、已有发现、限制和下一步建议，不生成凭空的“创新性分数”。

### 3.4 假设与反证

用户可提出假设，系统也可建议候选；候选不能直接进入已验证结论。

假设卡包含：命题、适用条件、支持证据、反对证据、替代解释、可观察的区分结果、待补充材料、用户决定。

检索不能只寻找支持性材料。系统应保存查找反例的查询及结果，无结果也保留检索范围，而非输出“已证明正确”。

### 3.5 验证卡

验证卡将候选假设转为可评审计划：

- 要区分哪些解释，哪些观察会支持或削弱它们；
- 自变量、评价指标、比较基线和需要固定的条件；
- 数据、样本或资源的获得方式与适用范围；
- 复现基线、对照、重复试验或消融的具体安排；
- 分析方法与不确定性报告方式，由领域要求决定；
- 停止条件、预算和失败/无法判断的判据。

内部确认后保存不可变版本和时间戳，修改另建版本。内部冻结计划不等于已向公共注册平台完成预注册。探索性分析允许存在，但必须与原计划区分。

AI 示例：对相同数据划分和评价程序比较不同 k，记录额外检索与生成成本；区分上下文长度、文档质量与数量变化的影响。具体重复次数及统计分析需根据实际任务确定，不能给所有研究套一个固定阈值。

### 3.6 实验记录与结论更新（后续模块）

接入运行前，记录代码版本、数据版本、配置、环境、资源和计划版本。结果包括成功、失败、负面结果和无法判断；保存原始日志与输出。

结果观察和解释分开记录。实验结论只能适用于实际测试条件，不自动推广到整个领域。判定采用 supported / challenged / inconclusive 等项目状态，不声明算法代替研究者证明科学命题。

### 3.7 写作与变更影响（后续模块）

导出相关工作、方法比较、实验计划和结论时，引用项目中已确认的证据与决策。

新增或修正文献、撤销提取值、导入实验结果后，根据依赖关系找出可能受影响的矩阵、假设、图表和报告段落，交给用户复核。保留影响记录，不直接覆盖历史结论。

## 4. 领域对象与来源关系

```text
ResearchProject
  ├─ ResearchQuestion（版本）
  ├─ SearchProtocol（版本）→ SearchRun → ScreeningDecision
  ├─ SourceDocument / DocumentVersion / EvidenceChunk
  ├─ StudyRecord → ExtractedField / Observation
  ├─ ComparisonSet → ComparabilityAssessment
  ├─ ConflictCandidate / ResearchGap
  ├─ Hypothesis → 支持/反对证据 + AlternativeExplanation
  └─ ValidationPlan（版本）→ 后续 ExperimentRun → Interpretation
```

新对象都有 owner_id、project_id、来源记录和版本。模型提出的内容、程序核验结果与用户确认分开保存。领域内的“一个研究”和“一篇文献”分别标识，避免重复计数。

项目记忆主要由这些权威记录构成：问题如何改变、哪些材料已筛选、哪些字段已确认、哪些实验失败、为什么改变方案。摘要或向量索引是可重建视图，不能替代原始记录。

## 5. 与已有项目的衔接

保留第一阶段 API/Worker、任务/报告版本、检查点、原文片段与预算能力。

新增以 project_id 组织的研究应用服务。当前任务是一次执行，项目可以关联多次任务，跨任务复用已确认记录。

把目前 Finding 的自由文本逐步升级为 StudyRecord 和字段级提取；Claim 增加对观察、假设与研究条件的关联。报告从矩阵和证据生成，不能跳过这些产物直接成为唯一结果。

LLM 承担候选提取、解释与表达；程序检查来源存在性、版本、字段单位、比较规则和结果状态；用户确认筛选、关键提取值和研究决策。无需为每一项功能新建一个自主 Agent。

## 6. 首个可交付模块与验收

首个模块只实现问题卡、筛选记录、字段级证据矩阵与假设验证卡。输入一个研究问题、用户提供的文献或检索候选；输出可编辑、可追溯的项目材料。

暂不自动运行实验、做元分析、判定全球新颖性或监控所有新论文。

验证方式：选择一个确定学科的真实课题和约 20–30 篇材料，由研究者制作字段及来源标注；同一输入分别使用“通用 Agent + Skill”和新系统。

固定任务与材料，比较：

| 指标 | 计量方式 |
|---|---|
| 字段提取准确性 | 和人工标注匹配的字段数 / 可评价字段数；缺失值单列 |
| 原文定位可核验性 | 正确定位且支持字段的条目 / 被核验条目 |
| 比较判断准确性 | 与领域研究者确认的可比/不可比/不确定判断一致率 |
| 人工修正时间 | 从初版材料到可用版本的实际时间 |
| 覆盖与遗漏 | 对提供材料内关键发现的覆盖，不能代表全部文献覆盖 |
| 研究决策价值 | 研究者能否据材料解释纳入、对照与验证计划选择 |
| 成本与延迟 | 相同材料下的调用成本与总用时 |

预算、材料范围、评审规则在比较前确定。是否继续扩展由实际收益决定，不能仅凭模型自评分通过。

## 7. 方法参考与适用边界

- PRISMA 2020 及其展开清单提供系统综述报告中筛选、提取和自动化使用的记录要求。借鉴可追溯记录设计，不能据此宣称所有学科或当前产品符合系统综述标准：https://www.prisma-statement.org/prisma-2020-checklist ，https://www.prisma-statement.org/s/PRISMA_2020_expanded_checklist-yc78.pdf
- Center for Open Science 对计划性与探索性工作的区分，为保存计划版本、分析变更和实际结果提供参考：https://www.cos.io/initiatives/prereg

该方案为产品设计建议，不是已完成的软件能力或对研究正确性的保证。确定研究领域后，优先细化字段 schema、可比性规则和人工评价集。
