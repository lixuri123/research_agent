# 轻量记忆架构

状态：核心存储、管理接口和预算组装已实现。本文取代 `memory_architecture_v2.md` 中的重型落地路径；不同工作流节点何时读取记忆，另行决定。

## 目标与边界

记忆用于减少跨会话重复劳动、恢复任务上下文和复用经过验证的方法。研究事实仍以原始文献和当前证据链为准；历史结论只提供查找线索，不能直接变成新报告的证据。

第一版只采用已有本地 SQLite 和文件系统。近期窗口由 SQLite 限量查询实现；Redis 或内存队列可以作为后续缓存，不影响正确性。部署使用既有 Postgres 时，记忆表沿用同一数据库连接。记忆本身不引入 Milvus、Neo4j 或自动 Skill 进化。

## 四层存储

| 层 | 存放内容 | 权威来源与失效方式 |
|---|---|---|
| 近期消息 | 当前会话最近消息的 ID 与必要内容；可用内存队列或 Redis | SQLite 会话历史是权威来源；缓存丢失后可重建 |
| SQLite | 完整会话事件、任务记录、记忆元数据、来源和状态 | 持久化权威记录；不得因消息离开近期窗口而删除 |
| Markdown | 整理后的偏好、项目知识与历史任务摘要 | 正文文件与 SQLite 记录以稳定 ID、版本和内容哈希关联 |
| Skill 文件 | 经过验证的可重复步骤 | 版本化发布；候选方法不自动成为可用 Skill |

消息队列只决定近期候选，不决定模型上下文大小。模型输入由组装器按完整请求的 Token 预算选择。

## 记忆的含义

- **会话历史**：完整发生记录，可回放或追溯；并非每次都送入模型。
- **语义记忆**：明确偏好、项目约束或可复用知识。研究结论必须带来源与适用时间。
- **情节记忆**：某次任务的目标、条件、行动、结果和经验摘要，引用原始任务与事件，不复制整段聊天。
- **程序记忆**：经过评测的方法，以 Skill 文件承载，写明适用条件、步骤、验证和失败处理。

“短期/长期”表示保留与使用策略，不是和语义、情节、程序并列的内容类型。Skill 是可执行工作方法，不能自行扩大工具权限。

## 数据关联与生命周期

SQLite 为每条整理后的记忆记录稳定 `memory_id`、类型、所有者、作用范围、来源引用、文件路径、内容哈希、版本、创建/更新时间和状态。作用范围至少区分会话、项目与个人；检索必须先用可信调用上下文限定范围。

Markdown 文件包含标题、来源引用、范围和正文；SQLite 保存更新时间。适用条件仍需在正文中明确。文件与 SQLite 版本或哈希不一致时，拒绝把该条目组装进模型上下文，避免静默采用其中任意一份。更新先写临时文件并原子替换，再提交可见的新版本；中断后的不一致需人工核对修复。

状态先保持简单：`candidate`、`active`、`stale`、`deleted`。从历史对话自动提取的内容先是候选；明确用户偏好可在核实原话后激活；科研结论若来源变化则失效。删除应同时使 SQLite 索引和 Markdown 正文不可用于召回。已有报告和原始会话的保留策略单独管理。

Skill 由有效任务经验提炼为候选，经测试和人工审查后发布新版本；旧版本可回退。一次成功不构成充分验证。第一版只支持人工编写或审查 Skill，不做自动改写。

## 统一接口与召回

保留 `MemoryManager` 作为门面，逐步实现会话追加与读取、候选记忆写入、确认/失效、按范围召回、上下文组装。旧模块保留适配空间，但不能让无来源的旧记录自动进入可信长期记忆。

召回顺序是：可信身份与范围过滤 → 状态与适用条件过滤 → SQLite 关键词和元数据查找 → 读取 Markdown 并核对版本 → 相关性筛选 → Token 预算内组装。没有合格结果就返回空；`top_k` 是上限，不要求凑满。组装结果记录入选 ID、来源、原因、估算 Token 和省略项，方便追查错误召回。

预算计算为：模型上下文上限减去系统提示、当前输入、工具/证据内容、输出预留及安全余量。近期消息条数只是缓存参数，不能代替 Token 预算。最终发送前检查完整请求。

## 落地顺序与验收

1. 保存完整会话事件并能恢复；建立统一的近期消息读取与完整请求预算。先不启用长期记忆。
2. 保存可查的任务摘要与少量明确偏好，建立 SQLite 元数据和 Markdown 正文关联、范围校验与失效机制。
3. 从真实跨会话任务中评测召回：比较无长期记忆、按需查历史、自动召回三种方式的正确率、重复工作、耗时和 Token 成本。只有收益明确时再扩展自动提取或语义索引。
4. 将反复成功且经过验证的方法人工沉淀成 Skill；自动生成和自进化留待独立评测。

最低验收：重启后历史可恢复；近期窗口不会删除历史；越界、失效或文件版本不一致的条目不进入上下文；历史研究结论不能绕过当前证据核验；组装不超过预算。当前 `recall_node` 是空实现，本实现不会自动改变主流程行为。

目前的来源 ID、评测 ID 和审核者由调用方提供，尚未与原始会话事件或评测产物做自动存在性校验；激活与 Skill 发布是人工审核动作。Skill 文件已版本化保存，但研究工作流尚无 Skill 加载与执行器。跨会话自动提取、滚动摘要、来源变化自动失效与有无记忆对照评测仍属于后续工作。
