# 生产级 Agent 系统架构设计

> 历史文档：保留设计与实施背景，当前结构请参阅 [目录说明](../architecture/directory-structure.md)。

> 面向论文检索、内容总结、研究报告生成等多智能体场景，设计一套可扩展、可观测、可靠、安全的完整 Agent 架构。本设计在当前 `research_agent` 项目（LangGraph + 五智能体）基础上升级，补齐记忆、上下文、治理、可靠性等生产级能力。

## 1. 设计目标

1. **可编排**：多 Agent 能顺序、并行、循环、子图委托地协同。
2. **有记忆**：具备短期 / 长期 / 实体 / 过程四类记忆，支持压缩、遗忘、检索、拼接。
3. **可观测**：每次运行全程可追踪、可回放、可评测。
4. **可靠**：超时、重试、熔断、降级、幂等、检查点全链路覆盖。
5. **可治理**：权限、沙箱、内容安全、人工介入、审计。
6. **可扩展**：分层解耦，模型、工具、知识、记忆后端均可替换。

## 3. 分层详解

### 3.1 接入层（Interface Layer）

统一的请求入口，屏蔽底层差异，负责会话与流式。

| 组件 | 职责 |
|------|------|
| REST API（FastAPI） | 同步 / 异步任务提交、状态查询、结果获取 |
| CLI / SDK | 开发调试与脚本调用 |
| 消息通道适配器 | 微信 / 飞书 / Slack 等 IM 接入 |
| 会话管理器 | 绑定 `thread_id`，维护会话生命周期 |
| 流式网关 | SSE / WebSocket 流式输出中间结果 |

### 3.2 编排层（Orchestration Layer）—— 核心

基于 LangGraph 构建有状态图，是本系统的"大脑"。

**协同范式（多种并存）**：

| 范式 | 说明 | 适用场景 |
|------|------|---------|
| 顺序流水线 | plan → retrieve → read → write → review | 科研报告（当前已实现） |
| 规划-执行-反思 | Plan → Execute → Reflect 循环 | 复杂开放任务 |
| 并行 Worker | 多个子任务并行执行再汇聚 | 多主题并行检索 |
| 子图委托 | 主图把子任务委托给独立子图 | 模块化复用 |
| 多 Agent 辩论 | 多个角色生成 + 相互批判择优 | 高精度决策 |

**编排能力清单**：

- **任务分解**：Planner 把目标拆成有依赖关系的子任务 DAG。
- **条件路由**：`add_conditional_edges` 按状态字段选择下一节点。
- **循环反馈**：Reflector 评分不达标 → 回到执行器修订，受 `max_iterations` 约束。
- **人工介入（HITL）**：`interrupt()` 暂停图执行，等待人工审批后 `resume` 继续。
- **检查点（Checkpoint）**：`Checkpointer` 持久化图状态，支持暂停/恢复/重放。
- **并行扇出**：`Send` API 动态并行分发子任务。

**角色模型（通用化，超越科研五智能体）**：

```
Coordinator（主控） → Planner（规划） → Worker（执行，可多实例）
                    → Reflector / Critic（反思评估） → HITL（人工确认）
```

### 3.3 记忆层（Memory Layer）—— 重点

完整的记忆子系统，包含**四类记忆 + 三个处理环节**。

#### 3.3.1 四类记忆

| 记忆类型 | 语义 | 存储后端 | 生命周期 |
|---------|------|---------|---------|
| **短期记忆** | 当前会话的活跃上下文，滑动窗口 | Redis / 内存 | 会话内，超窗遗忘 |
| **长期记忆** | 跨会话的语义知识，向量检索召回 | Milvus | 持久，可检索 |
| **实体记忆** | 关于实体（人/组织/概念/术语）的事实集合 | Neo4j 图数据库 | 持久，可累积 |
| **过程记忆** | 曾经执行过的任务轨迹（情景） | Postgres / 向量 | 持久，可复盘 |

#### 3.3.2 记忆生命周期（写入 → 巩固 → 读取）

**① 记忆编码器（写入）**
- 新信息进入后：结构化（转成 `MemoryItem`）、分类（语义/实体/事件）、去重（相似记忆合并）。

**② 记忆巩固器（压缩与遗忘）**
- **滑动窗口**：短期记忆只保留最近 N 条 / 最近 M token。
- **滚动摘要**：窗口溢出时，用 LLM 把旧内容总结成摘要写入长期记忆。
- **递归分层摘要**：大规模历史用多级摘要（类似 MemGPT 分层记忆）。
- **实体抽取**：从对话中抽取实体及关系，写入实体记忆。
- **遗忘策略**：低相关度 / 长期未访问记忆降权或淘汰。

**③ 记忆读取（检索与拼接）**
- 以当前 query 为锚点，从长期 / 实体 / 过程记忆检索相关片段。
- 按相关度排序 + 截断，与短期窗口一起拼入最终 prompt。

#### 3.3.3 记忆存储后端选型

| 方案 | 短期 | 长期 | 实体 | 过程 |
|------|------|------|------|------|
| A（轻量） | Redis | Milvus | Milvus（实体标签） | Milvus |
| B（标准） | Redis | Milvus | Neo4j 图谱 | Postgres |
| C（官方抽象） | LangGraph Store | LangGraph Store | LangGraph Store | LangGraph Store |

> 推荐 **方案 B**：实体关系用图数据库表达力最强；其余复用向量库。方案 A 无需新增依赖，适合快速落地。

### 3.4 工具层（Tool Layer）

- **注册中心**：统一注册工具，声明 Schema（参数类型、描述）。
- **工具选择**：Agent 根据任务语义自主选择工具（规则 / LLM 决策）。
- **执行沙箱**：代码类工具在隔离环境运行，限制网络 / 文件 / 权限。
- **权限控制**：工具分级授权，敏感操作需审批。
- **降级与重试**：工具失败自动降级到备选工具（如论文检索失败 → 网页检索）。

### 3.5 知识层（Knowledge Layer）

- **文档解析**：PDF / Word / HTML / Markdown 解析。
- **向量索引**：分块 + Embedding + 向量库（Milvus）。
- **知识图谱**：实体关系抽取，图数据库存储，支持图查询推理。
- **RAG 检索器**：混合检索（向量 + 关键词 + 图谱）+ Rerank 重排。

### 3.6 模型层（Model Layer）

- **LLM 网关**：统一封装，屏蔽不同供应商差异。
- **多模型路由**：按任务类型 / 成本 / 延迟路由到不同模型（强模型做规划反思，弱模型做摘要）。
- **结构化输出**：`with_structured_output` 约束 + 容错解析。
- **Embedding / Rerank**：向量化与重排序模型统一管理。
- **限流与配额**：调用限流、token 预算、成本追踪。

### 3.7 基础设施层（Infrastructure Layer）

| 组件 | 用途 |
|------|------|
| Milvus | 向量库（长期记忆 / 知识库） |
| Neo4j | 图数据库（实体记忆 / 知识图谱） |
| Redis | 缓存 / 短期记忆 / 任务队列 / 检查点 |
| Postgres | 元数据 / 过程记忆 / 审计日志 |
| 消息队列 | 异步任务 / 事件驱动 |
| 对象存储 | 文档 / 报告文件 |

## 4. 横切关注点

### 4.1 安全与治理

- **沙箱执行**：工具调用在隔离环境，限制高危操作。
- **权限分级**：工具 / 数据按角色授权。
- **内容安全**：输入输出内容审核，拦截违规内容。
- **人工介入**：高危动作（发送、删除、发布）强制 HITL 确认。
- **审计日志**：全程记录谁在何时执行了什么，可追溯。

### 4.2 可观测性

- **追踪**：LangSmith / OpenTelemetry 记录每次运行的节点、LLM、工具调用。
- **日志**：结构化日志，含 `trace_id` / `thread_id` 关联。
- **指标**：延迟、token 用量、成本、成功率、重试率。
- **评测**：任务完成率、引用准确率、响应延迟三维度 + 回归集。
- **回放**：基于 checkpoint 重放任意历史运行，定位问题。

### 4.3 可靠性

| 机制 | 说明 |
|------|------|
| 超时 | LLM / 工具调用设置超时预算 |
| 重试 | 指数退避重试，限次 |
| 熔断 | 下游连续失败时熔断，避免雪崩 |
| 降级 | 主工具失败降级备选，Milvus 不可用降级关键词匹配 |
| 幂等 | 任务提交幂等，重复请求不重复执行 |
| 检查点 | 中断可恢复，不丢状态 |
| 最大迭代 | 循环上限，防止失控 |

## 5. 上下文工程（Context Engineering）

上下文是 Agent 的"带宽"，需精细管理：

1. **Token 预算**：为 system / memory / tools / history 分配预算。
2. **上下文压缩**：超预算时先摘要再拼接（与记忆压缩协同）。
3. **检索增强**：只注入与当前任务相关的记忆 / 知识片段。
4. **上下文裁剪**：滑动窗口裁剪旧消息，保留关键信息。
5. **结构化提示**：system prompt 分模块（角色 / 约束 / 工具 / 输出格式）。

## 6. 端到端请求生命周期

```
1. 用户请求 → 接入层（会话绑定 thread_id）
2. 编排层 Coordinator 接收
3. 上下文引擎：从记忆层检索相关片段 + 组装 prompt
4. Planner 任务分解 → 生成子任务 DAG
5. Worker 并行执行 → 按需调用工具层 / 知识层 / 模型层
6. Reflector 评估结果 → 不达标回退修订（受 max_iterations 约束）
7. HITL：高危操作 / 未达标时人工确认
8. 记忆巩固：把本次有价值的信息写入记忆层
9. 输出 → 接入层返回（流式）
10. 全程记录 trace / 指标 / 审计日志
```

## 7. 关键技术决策与权衡

| 决策点 | 选择 | 理由 | 权衡 |
|--------|------|------|------|
| 编排框架 | LangGraph | 有状态、可检查点、支持 HITL | 学习成本略高 |
| 实体记忆 | Neo4j 图谱 | 关系表达力强 | 多一个重依赖 |
| 压缩策略 | 滚动摘要 | 简单通用 | 长历史需升级分层摘要 |
| 检查点后端 | Redis | 复用现有缓存 | 大规模需换 Postgres |
| 多模型路由 | 网关 + 规则路由 | 简单可控 | 复杂场景需 LLM 路由 |

## 9. 从当前项目演进路线

当前 `research_agent` 已具备：编排层（五智能体）、工具层、知识层（Milvus）、模型层、可靠性（部分）。演进分三阶段：

**阶段一（快速补齐）**：新增记忆层（短期 Redis + 长期 Milvus + 压缩 + 拼接），复用现有依赖。

**阶段二（生产加固）**：加 Checkpointer（暂停/恢复）、HITL 真审批、工具沙箱、审计日志、评测回归。

**阶段三（能力扩展）**：实体记忆（Neo4j）、过程记忆、多模型路由、多 Agent 辩论、消息通道接入。
