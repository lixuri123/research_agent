# 普通 Agent 的长期记忆

普通任务按 [上下文路由](context-assembly.md) 决定是否在规划前自动检索长期记忆：追问、关联任务与明确个人历史问题允许召回，独立问题默认不召回。科研专用图没有改动。

## 筛选与预算

沿用本地中文二元词项、英文词项匹配，不调用模型或 embedding 服务，不依赖向量库。只召回当前 owner 的 active、文件哈希校验通过的 semantic / episodic 条目。project 条目只匹配当前工作空间（workspace_id 优先于 project_id），session 条目只匹配当前会话。候选、失效、删除、篡改和其他范围的条目不使用。

相关性命中后按当前项目、当前会话、个人通用的范围优先，再按匹配分数、更新时间排序；无关条目不补位。procedural 条目继续通过原有 Skill 审核和加载链路使用，不混入自动背景。

默认最多 5 条，正文及来源元数据序列化后总计不超过 12000 UTF-8 bytes，单条正文最多 2000 字符；摘录标记 truncated。这只是记忆背景预算，不是整个任务上下文上限。

```dotenv
AGENT_MEMORY_TOP_K=5
AGENT_MEMORY_MAX_BYTES=12000
```

设 `AGENT_MEMORY_TOP_K=0` 可关闭自动背景及 memory_search 返回的记忆。重启 Worker 后设置生效。

## 执行与恢复

首次选择保存在新普通任务的 `agent_context_sources/v1` 阶段；旧任务继续使用 `agent_memory/v1`。模型调用前重新检查状态、scope、version 和 hash；已失效、删除、修改或不可读取的条目不再直接注入。恢复任务沿用首次选择，不自动追加后来创建的记忆。更新后的条目需重新激活，再由新任务或显式搜索获取。

只读工具 `memory_search` 可用更准确的关键词补充历史。工具结果在再次进入提示词前重新校验，不提供记忆激活或写入能力。工具权限与 MCP 授权不从记忆推导。

正文放在用户请求中的独立历史背景区，不作为 system 指令。历史材料不是当前事实、外部证据或新授权；当前用户要求优先，重要结论仍需核对实际材料。已生成的计划和其他阶段产物不会因记忆失效而自动重写。

检索或校验失败时跳过对应背景，任务结果提供 warning；其他基础设施失败仍走原有任务错误处理。旧版已开始任务没有记忆阶段时，恢复不追加新自动背景。

## 使用与审计

在记忆面板创建条目并确认激活，再发送相关主题的普通 Agent 消息。按工作空间隔离时，project_id 填对应 workspace_id。任务输出不会自动成为可信记忆。

新任务通过 `GET /tasks/{id}` 的 `result.context` 查看选择来源、估算占用和省略原因，`context_selected` 事件记录首次选择；旧任务继续使用 `result.memory_context` 和 `memory_recalled`。搜索结果保留在工具 trace 中。

失效/删除阻止未来读取和直接注入，但不会自动清除旧任务审计中的正文或摘录。完整数据遗忘需另行处理历史任务与备份。

本次补通用读取/召回，不实现自动记忆提炼、自动激活、跨会话进展总结或科研专用流程。
