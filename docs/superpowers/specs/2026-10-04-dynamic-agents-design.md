# 动态 Agent 协作设计

用户已在会话中批准主 Agent 持续决策、按需委派子任务，并要求直接实施。

## 执行模型

普通任务的 personal_agent 保持唯一交付责任。它获得 agent_spawn、agent_status、agent_wait、agent_cancel 工具；每次 spawn 明确目标、必要上下文及完成标准。任务角色不固定为 Planner/Reader/Writer。通用子 Agent 自主进行模型与工具循环，研究子任务调用现有 LangGraph 研究流程。

同一 Worker 内使用有界线程池执行子任务，默认最多两个同时执行、每个父任务最多六个子任务、子 Agent 最多八步。第一版只有一层委派，不实现任意消息网、递归生成或独立子进程。主 Agent 可在结果返回后追加核查任务。

## 状态与恢复

每个子任务拥有稳定 ID、目标、上下文、完成标准、模式、状态、步骤和结果。复用父 run 的阶段表保存注册表及各子任务独立命名空间下的决策和观察；spawn 的 operation_id 保证恢复不重复创建。queued/running 子任务恢复后继续，终态结果不重复执行。进度及结果记录为父任务事件，供现有任务详情查询。

主任务完成前必须处理所有尚未结束的子任务。cancel 在模型和工具边界阻止后续动作，已开始的外部请求可能完成；关闭父任务时取消并等待本地工作线程收束。租约检查仍由父 Worker 执行，不允许失效 Worker 提交产物。

## 权限、预算及结果

子 Agent 工具目录继承父目录的只读能力；禁止递归委派及写入提案/有副作用 MCP。显式上下文作为任务数据，不拼入系统提示词。Skill 指令和历史记忆沿用现有优先级规则。所有模型调用共用线程安全的父 Budget，不为子任务重新分配完整调用或时间预算；文献额度由协作控制器限制。

子任务输出是供主 Agent 检查的材料，不自动成为已验证结论。研究子任务运行现有证据审核流程、禁用子流程内人工审批、返回其真实 completed/partial/insufficient_evidence 状态；不在子流程发布报告，最终交付仍由主 Agent 决定。子流程不调用需要单独授权的能力。

## 验证

离线模型及工具替身验证两篇论文并行阅读、追加核查、主 Agent 汇总；验证权限缩小、共享预算并发预留、取消、失效租约、崩溃恢复、spawn 幂等及未结束子任务阻止完成。回归现有个人 Agent 记忆、工作流、Worker 和 API 测试。不调用真实付费模型。
