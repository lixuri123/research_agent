# 科研助手完整工作台设计

## 目标

为现有 FastAPI 科研助手提供可直接使用的 React 工作台，覆盖研究任务、运行事件、报告审批与证据、会话消息、记忆和 Skill 管理。开发期使用 Vite，生产构建由 FastAPI 在同一 `8000` 端口托管。

## 信息架构

工作台采用固定侧栏与内容区布局，包含“总览”“新建研究”“研究任务”“会话”“记忆”“Skills”六个入口。总览展示服务健康状态、任务统计、近期任务和快捷操作；研究详情在同一界面展示状态时间线、预算结果、报告 Markdown、引用和审批操作。

## 视觉方向

界面采用偏研究工具的编辑部风格：暖白背景、深墨色文字、靛青主色与琥珀状态强调，大标题使用衬线字体、数据与正文使用清晰无衬线字体。避免模板化渐变和过量卡片，强调长报告阅读、证据追踪和高信息密度。

## 架构

- `frontend/`：React、TypeScript、Vite 单页应用。
- `frontend/src/api.ts`：集中封装现有 REST API。
- `frontend/src/App.tsx`：工作台导航与页面状态编排。
- `frontend/src/components/`：研究、报告、会话、记忆和 Skill 的独立视图。
- FastAPI 新增分页任务列表接口，并在存在 `frontend/dist` 时托管静态前端。
- Vite 开发服务器将 `/api` 不作前缀处理，直接代理现有根路径 API 到 `127.0.0.1:8000`。

## 数据流

提交研究后前端保存任务 ID，立即进入任务详情并每 2 秒轮询任务与事件；进入终态后停止轮询。等待审批时读取当前报告版本，并以明确的批准/拒绝操作提交审批。会话、记忆和 Skill 页面直接复用现有接口；会话由用户输入或从研究任务的 `session_id` 进入。

## 后端补充

新增 `Repository.list_runs()` 和 `GET /research?limit=&offset=`，返回任务基本信息及原始请求主题。现有单任务、事件、报告、审批、会话、记忆和 Skill 接口保持兼容。静态挂载放在全部 API 路由之后，避免遮蔽 API。

## 错误处理

所有请求错误转为统一中文提示，并保留服务端 detail。健康检查失败时顶部显示离线状态。轮询失败不会清空已展示数据；用户可手动重试。危险操作（拒绝报告、删除记忆）要求二次确认。

## 环境与部署

Python 依赖继续由 uv 管理，以 `pyproject.toml` 和 `uv.lock` 为唯一依赖来源。前端使用 npm 管理浏览器依赖。Docker 多阶段构建前端，再使用 uv 冻结安装 Python 生产依赖。

## 验证范围

遵循“少量测试”要求：只新增一个后端任务列表测试；前端以 TypeScript 检查和生产构建为主；最后执行一次健康检查、页面加载和关键 API 冒烟验证。不增加大规模组件测试或端到端测试矩阵。
